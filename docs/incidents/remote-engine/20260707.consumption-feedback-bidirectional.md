# 20260707 — 消耗反馈闭环：getNetworkStress+1:N绑定

status: verified

## 背景

远程引擎消耗应显示在绑定的应力读取器上，并正确反馈到红石信号、tooltip 和 Ark HUD。

## 解决方案

**分层反馈架构：**

1. **数据通道** — `StressReaderBlockEntity.remoteEngineConsumption`（float，NBT 同步）
   - 客户端 tooltip 直接读字段，不调 StressLinkService（服务端返回 null）
   - `setRemoteEngineConsumption()` 调用 `sendData()` + `sendBlockUpdated()` 立即同步

2. **推送时机** — 两个入口写回字段：
   - `pushToEngine()` 末尾写入聚合消耗
   - `onEngineNetworkChanged()` 末尾写入聚合消耗（Engine 本地负载变化时触发）

3. **getNetworkStress() 覆盖** — 返回 `super.stress + remoteEngineConsumption`
   - 使 comparator、tooltip 剩余容量自动扣减
   - 使 `pushToEngine()` budget 自动收敛：`C - (S + cons)` → Engine 容量自然减少
   - 不影响 Create 网络层（Create 读 `this.stress`，不是 getter）

4. **1:N 绑定** — `readerToEngine` 类型从 `Map<Pos, Pos>` 改为 `Map<Pos, Set<Pos>>`
   - `bind()` 用 `computeIfAbsent` 加入 Set
   - `getEngineConsumptionForReader()` 聚合 Set 内所有 engine stress
   - `onReaderDestroyed()` 遍历 Set 清所有 engine
   - `save/load` 格式不变（每行 engine→reader 元组）

## 教训

1. **`@Override` 不能用在 `getNetworkStress()` 上** — `KineticBlockEntity` 不定义该方法，只有 `StressGaugeBlockEntity` 有。需去掉 `@Override` 直接定义。

2. **编辑有时不持久化** — 多次出现 edit 工具返回成功但文件内容未变（被 git checkout 或之前 commit 覆盖）。今后每次 edit 后必须 `Read` 验证。

3. **Service 查询在 tooltip 中不可靠** — `addToGoggleTooltip()` 客户端调用，`StressLinkService.get(level)` 返回 null。必须用 NBT 同步字段。

4. **1:N 的 readerToEngine 不需持久化 Set** — `load()` 从 `engineToReader` 重建成 `computeIfAbsent(readerPos, k -> new LinkedHashSet<>()).add(enginePos)`，持久化格式无变化，向后兼容。

5. **收敛证明** — getNetworkStress 包含 consumption 后，pushToEngine 的 budget = C - S - cons_total。Engine 每 tick 更新本地消耗后 onEngineNetworkChanged 写入消费，但 pushToEngine 仅在 Reader 网络数据变化时触发，形成稳定反馈：consumption 变化 → 不立即 push → 下次 Reader tick 时 budget 收敛。
