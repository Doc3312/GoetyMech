# Forge Config 缓存陷阱：代码默认值 ≠ 运行时值

status: verified
date: 2026-07-13
source: 地面变形半径不生效调试

## 问题

添加新配置项 `slam_ground_deform_radius` 后，第一次跑游戏时 Forge 将代码默认值 `6.0` 写入了 `run/config/goetymech-common.toml`。后续代码将代码默认改为 `12.0`，但 ForgeConfigSpec 对于已存在的 key 不会用新默认覆盖——`config.get()` 始终返回 `6.0`。

## 根因

Forge 配置系统加载流程：

1. 启动时读取 `*.toml`
2. 如果 key 不存在 → 用代码默认值创建
3. 如果 key 已存在 → **直接使用文件值，忽略代码默认**
4. `defineInRange` 只校验文件值是否在 `[min, max]` 范围内，不校验是否等于新默认

## 教训

| # | 教训 |
|---|------|
| 1 | 修改已有配置项的代码默认值后，必须同时更新 toml 文件中的对应行，否则修改不生效 |
| 2 | 调试配置不生效的问题时，第一步应该检查 toml 文件中的实际值，而非代码中的默认值 |
| 3 | ForgeConfigSpec 没有 "判断值是否用户显式修改过" 的 API，无法区分用户设定 vs 旧默认遗留 |

## 涉及文件

- `config/ModConfig.java` — 配置定义
- `run/config/goetymech-common.toml` — 磁盘缓存
