# 多对话 `git add -A` 互相覆写问题

## 现象

本对话对 `StressArkHUD.java` 和 3 个纹理文件的修改（`fbd072a`、`bf77449`），被后续其他对话的 commit（`f227f93`、`1a37242`）静默覆写了。

原因是其他对话执行 `git add -A` 时，如果工作目录中这些文件的版本是旧的，就会把旧版本 staging 并 commit，冲掉前面对话的正确修改。

## 根因

`git add -A` 会把工作区所有 tracked 文件的当前版本加入 stage。如果两个对话并行或先后修改同一文件：
1. 对话 A 修改 → 提交 commitA
2. 对话 B 执行 `git add -A` → 如果 B 的工作区中该文件还是旧版本（例如对话 B 启动时拉的代码在 commitA 之前）→ 旧版本被 stage → commitB 覆盖了 commitA

## 解决

- **手指定文件 `git add`**：不要用 `git add -A`，改用 `git add src/main/java/.../StressArkHUD.java src/main/resources/.../engine_energy.png`
- **任务声索**：AGENTS.md 的多对话协同约束（`task-mgmt.mjs start`）应能帮助检测文件冲突，但前提是各对话都遵守
