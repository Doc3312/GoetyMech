# AutoCastDummyWand 误判为测试代码

## 背景

代码清理任务中，按类名含 "Dummy" 将 `AutoCastDummyWand` 判定为测试/虚拟物品进行注释和摘除注册。

## 根因

- 类名 `Dummy` 仅表示"不绑定实体法杖物品"，而不是"测试用虚拟物品"
- 该物品是 Flesh Casket 自动施法系统的核心组件：`FleshCasketEvents.java:192-194` 用它作为 `PhantomWandManager` 的代理法杖（staff proxy）
- 类文件 `AutoCastDummyWand.java` 实现了 `IWand` 接口，提供了 `SoulUsingItemHandler` cap，所有代码都是生产路径

## 影响

编译失败（3 errors），被迫 revert。

## 经验

1. "Dummy" 类名不应自动判定为测试代码。需检查是否有生产路径引用（`FleshCasketEvents`、`PhantomWandManager` 等）
2. 判定 legacy code 的 checklist 应包含：
   - 是否被生产代码 import/引用？→ 是则保留
   - 是否有模型/纹理/lang key？→ 缺失不一定代表是测试代码
   - 是否注册但不加入 creative tab？→ 合法，注册即可被能力系统引用
3. `build-log.txt` 中的 WARN 属于 "missing model"，不能反推注册项是测试代码
4. 清理前必须 grep 全仓库引用，不可只依赖直觉
