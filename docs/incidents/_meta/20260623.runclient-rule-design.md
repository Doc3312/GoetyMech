## 症状

AGENTS.md 中的 runClient 规则写成「IF 一个 task 的代码改动写完 THEN 自动执行」，导致 AI 在整个 task 完成后才跑一次 runClient。迭代修复（改 → 测试 → 发现没生效 → 再改）中，每轮修复后用户需要手动输入 gradlew runClient，AI 不会自动触发。

## 根因

规则的条件粒度过粗。将「task 完成」作为触发条件，而不是「每次生产代码变更」。
实际调试场景中，一轮修复写完 auto-commit 后就应该立即编译验证，不等全部 task 完成。

## 修复

将规则改为：IF auto-commit 包含 `src/` 下的 `.java` 文件 THEN 自动执行 runClient。
排除仅改配置文件（json/yaml/toml）和非代码文件（docs/）的提交。

同时将 AGENTS.md 的 6 条核心工作流规则从 `## 🚫 禁令` 区（文件末尾）移至文件开头独立的 `## 核心工作流（高优先级，每条规则均为 IF → THEN 格式）` 区域，确保新对话的 AI 第一时间读到。

## 经验提炼

- AGENTS.md 的流程规则必须用 IF → THEN 格式，不依赖 AI 的「判断」和「自觉」
- 触发条件必须是原子动作（auto-commit），而非宏观状态（task done）
- 核心流程必须放在文件开头，禁令/保护规则放在后面
