## 症状

`gradlew runClient` BUILD SUCCESSFUL，无 CRASH/Exception/Mixin 错误。
需游戏内实际测试电涌/流星雨/撕裂等多通道并行场景。

## 根因

### 根因 1：maxShots 不含 castUp → 通道在开火前终止

`ChannelTask` 的 `maxShots` 取自 `cs.shotsNumber()`，语义为"开火窗口"。但通道总时长 = maxShots，`castUp` 未计入。

| 法术 | castUp (config) | maxShots | 结果 |
|------|----------------|----------|------|
| SurgingSpell | 80 (SurgingChargeUp) | max(0, 60) = 60 | 通道 tick 60 终止，蓄力需 tick 80 → 永不触发 SpellResult |
| MeteorShowerSpell | 60 (MeteorShowerChargeUp) | max(20, 60) = 60 | 通道 tick 60 终止，刚蓄满来不及触发 coolAcc >= cd |

EverChargeSpell 的 `Cooldown() = 0`，但 `SurgingSpell` 覆盖为 `SurgingDuration = 6`，`MeteorShowerSpell` 覆盖为 `MeteorShowerDuration = 10`。由于通道在 tick 60 终止，连第一次 `coolAcc >= cd` 都等不到。

### 根因 2：ChannelTask.stop() 清除共享 PhantomWandManager

`ChannelTask.stop()` 无条件调用 `PhantomWandManager.clear(player)`。多通道并行场景下：

1. 撕裂（非蓄力）→ startSpell 创建 VoidRift (warmUp=115)
2. 电涌（蓄力）→ 加通道 → `PhantomWandManager.set()` 覆盖法杖，同时移除 PENDING_CLEAR
3. 电涌通道 60 tick 后结束（根因1）→ `stop()` 调 `clear()` → **PhantomWand 被清空**
4. VoidRift tick → `CastSpellTrapMixin` 读 PhantomWand → 空 → 退化为 `isSpellCasting(player)` → false → `discard()`

**已有 Mixin 未被充分使用**：`CastSpellTrapMixin.java`（@Redirect isSpellCasting → 检查 PhantomWandManager）在 2026-07-04 已建立并验证有效，但法杖被过早清除导致其失效。

### 根因 3：缺少"所有通道结束"后的统一清理

`stop()` 移除 `clear()` 后，需在 `onServerTick` 中所有 tasks 清空时补一次 `scheduleClear`。否则法杖永久残留。
