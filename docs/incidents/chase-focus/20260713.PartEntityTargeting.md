# PartEntity Targeting — VoidBlinkSpell 无法锁定多碰撞箱实体

## 现象

追猎聚晶无法锁定末影龙等多碰撞箱（multi-hitbox）实体。
`getTarget()` 始终返回 null。

## 根因

Goety 的 `Spell.getTarget()` 内部调用 `ISpell.entityResult()`，其 `ProjectileUtil.getEntityHitResult` filter 为：

```java
entity -> entity instanceof LivingEntity && !entity.isSpectator() && entity.isPickable()
```

末影龙的部件 `EnderDragonPart` 是 `PartEntity<?>` 而非 `LivingEntity`，被 filter 直接拒绝。
尽管 Goety 的 `MobUtil.getLivingTarget()` 已有 `PartEntity → parent` 解析能力，但 filter 层就拦截了，解析层从未到达。

## 修复

在 `VoidBlinkSpell` 中 override `getTarget(LivingEntity, int)`，复制 ray trace 逻辑但 filter 额外接受 `PartEntity<?>`：

```java
entity -> (entity instanceof LivingEntity && !entity.isSpectator() && entity.isPickable())
      || entity instanceof PartEntity<?>
```

然后通过 `MobUtil.getLivingTarget()` 将 PartEntity 解析为其父实体（如 `EnderDragon`）。

## 验证

- Goety 的弹射物类法术（`VoidShock`, `SurgingOrb` 等）采用 AABB 范围枚举 + 手动 PartEntity 解包模式
- `EnderDragonPart.isPickable()` 返回 true，可被射线检测
- `Level.getEntities()` 通过 Forge 补丁已包含 PartEntity
- 编译启动通过，无异常

## 教训

- `Spell.getTarget()` 继承的方法对多碰撞箱实体不工作，必须 override 修复 filter
- 直接复制 `ISpell.entityResult()` 逻辑比调用 `this.rayTrace()`（无法传入自定义 filter）更可控
- Goety 的 `MobUtil.LIVING_OR_PART` 谓词已预定义，可复用
- `Entity.level` 在 Parchment mappings 下为 `private`，需用 `Entity.level()` getter
