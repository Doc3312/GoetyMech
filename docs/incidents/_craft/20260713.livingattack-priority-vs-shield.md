# LivingAttackEvent 优先级：Prototype 小伤害免疫 vs StressShield

status: verified

## 背景

Prototype 有小伤害免疫（`damage <= threshold` → 免费取消），StressShield 消耗护盾值吸收伤害。两者都监听 `LivingAttackEvent`。

## 发现

**优先级决定了消耗顺序**：
- StressShield 跑 `HIGHEST` → 永远先拦截伤害 → 原型小伤害免疫成死代码
- 史莱姆 2.0 伤害本应被原型免费取消，却被盾消耗了护盾值

## 教训

1. **Forge 事件优先级是关键的**，同个 event 的多个 handler 必须明确谁先处理。消耗性资源（盾值）应该在免费免疫之后执行。
2. `Player.hurt()` 对 `hurtTime` 的处理与 `LivingEntity.hurt()` 不同，用 `hurtTime` 做护盾冷却不可靠。改用盾内置冷却（`gameTime - lastHurtTick` + 额外阈值）更稳定。
3. `LivingAttackEvent` 的 `setCanceled(true)` 必须在所有 SKIP 分支也调用，否则 `hurt()` 继续执行设 `hurtTime` → 受击效果播放。

## 修复

- `PrototypeEvents.onLivingAttack` → `EventPriority.HIGHEST`
- `StressShieldEvents.onLivingAttack` → 默认 NORMAL
- 冷却守卫从 `gameTime <= lastHurtTick` 改为 `gameTime - lastHurtTick < 5`
- SKIP 分支加 `event.setCanceled(true)`
