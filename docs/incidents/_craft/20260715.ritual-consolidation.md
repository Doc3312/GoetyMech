## 经验提炼

### ritual_type vs craftType 是正交的

| 字段 | 控制 | 注册位置 |
|------|------|---------|
| `ritual_type` | `finish()` 逻辑（Java 类） | `ModRituals.java` → `DeferredRegister<ModRitualFactory>` |
| `craftType` | 结构方块要求（`IRitualType`） | `ModRitualTypes.java` → `RitualType.addRitualType()` |

**不需要为每个 `craftType` 都注册一个对应的 `ritual_type`。** 标准 `goety:craft` 可用于任意 `craftType`，因为 `finish()` 逻辑完全相同。

### 何时需要自定义 `ritual_type`

- 需要 **保留激活物品的 NBT**（如升级类仪式）
- 需要 **特殊产出逻辑**（如判断条件、副产物）
- 需要 **多物品交互**（合成多个结果）

不需要的情况：产出逻辑就是"消耗激活物品 → 产出配方结果"的，直接用 `goety:craft`。

### 注册模式

```java
// ✅ 推荐：一个通用 upgrade，处理所有 NBT 保留需求
RITUALS.register("upgrade", () -> new ModRitualFactory(UpgradeRitual::new));

// ❌ 废弃：每个升级物品单独注册一个 ritual_type
// RITUALS.register("upgrade_casket", ...);
// RITUALS.register("upgrade_monument", ...);

// ❌ 废弃：等价于 goety:craft 的冗余注册
// RITUALS.register("mechanical", ...);
```

### 保留 NBT 的正确方式

```java
// UpgradeRitual.finish() 中：
if (activationItem.hasTag()) {
    CompoundTag tag = activationItem.getTag().copy();
    tag.remove("flesh_casket_cooldown");  // 选择性移除
    result.setTag(tag);  // 复制其余所有 NBT
}
```
