# Structure Search API 兼容性问题

status: verified

## 现象

神行聚晶渐进式搜索实现时，尝试参考 ExplorersCompass 的 `checkStructurePresence` + chunk 螺旋方案，
但 1.20.1 Parchment mappings 下编译报错：

1. `StructureCheckResult.CHECK_NOT_STARTED` — "找不到符号"
2. `StructurePlacement.isStructureChunk(ChunkGenerator, RandomState, int, int)` — RandomState 参数获取复杂
3. `HolderSet.Named` — import 正确但 Parchment 映射下无法解析
4. `level.getChunkSource().getGeneratorState().getPlacementsForStructure()` 返回 `List` 而非 `Set`

## 根因

Parchment mappings (2023.09.03-1.20.1) 是 Mojmap 上叠加参数名和 javadoc 的社区映射，
某些底层 Minecraft 类/内联接口签名与直 Mojmap 有细微差异。

## 解决方案

不用 `checkStructurePresence` + chunk 螺旋，
改用 Vanilla `ServerLevel.findNearestMapStructure(TagKey, BlockPos, int, boolean)` 做渐进式 radius 递增。

该 API 在 Parchment 下稳定可用，且：
- 自动处理 placement 路由
- 返回真正的全局最近结构（官方保证）
- 无需手动处理 `START_PRESENT / CHECK_NOT_STARTED` 两步确认

## 教训

参考 Fabric/NeoForge 模组的源码时，注意它们用的映射（Yarn / Mojmap / Parchment）可能与本项目不一致。
`StructureCheckResult` 的 enum 和 `StructurePlacement` 的 inner class 在 Parchment 下可能有兼容问题。
优先使用 Vanilla 公开 API 如 `findNearestMapStructure`。
