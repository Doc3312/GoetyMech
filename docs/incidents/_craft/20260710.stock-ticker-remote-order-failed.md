# Stock Ticker 远程 GUI — 跨维度/远距离失败记录

status: superseded
date: 2026-07-10
slug: stock-ticker-remote-order-failed
domain: _craft

## 目标

通过聚晶远程打开 Create Stock Ticker 的请求下单 GUI，支持远距离（同维度任意距离 + 跨维度）。

## 尝试过的方案

### 方案 1 — 直接复用 Create 的 `interactWithLogisticsManagerAt()`

路径：`SpellResult` → `StockTickerInteractionHandler.interactWithLogisticsManagerAt()`
- 问题：`StockKeeperCategoryMenu.stillValid` 里的距离检查（`getBlockReach + 4`）在远距离时关闭面板
- 修复：自己写 MenuProvider，用匿名子类覆写 stillValid 跳过距离检查 → ✅ 移动/滑翔修复

### 方案 2 — 客户端假 BE（S2C 包注册）

路径：`SpellResult` 先发 `S2CRegisterStockCachePacket` → 客户端创建假 `StockTickerBlockEntity` → `LevelMixin` 拦截 `getBlockEntity` 返回缓存
- 问题：`S2CRegisterStockCachePacket` 走 ModNetwork 频道，`ClientboundOpenScreenPacket` 走 Forge/Minecraft 频道，**两个不同频道不保证客户端处理顺序** → 竞态（registration 包可能晚于 openScreen 到达）→ createOnClient 找不到 BE → GUI 打不开
- 另：服务端缓存 `CrossDimStockCache.SERVER_CACHE` 污染了所有维度的 `Level.getBlockEntity` 查询，导致假包（phantom package）和卡顿
- 修复失败

### 方案 3 — 在 createOnClient 中内联创建假 BE

路径：移除 S2C 包，直接在 `StockKeeperRequestMenuMixin.createOnClient` 中 `@Inject HEAD cancellable=true` 创建假 BE
- 问题：假 BE 没有 `level` 字段，`behaviours` 未初始化，部分 Screen 操作（如 refreshClientStockSnapshot）发送的 C2S 包因距离检查被丢弃
- 现象：GUI 能打开但出现假包（phantom package，显示存在但实际上不存在的物品）、取物品卡顿
- 修复失败

### 方案 4 — 绕过 Create 的 BE 依赖（BlockEntityConfigurationPacket Mixin）

路径：`BlockEntityConfigurationPacketMixin` @Inject HEAD 拦截 `PackageOrderRequestPacket.handle()` 跳过 `pos.closerThan(player.blockPosition(), maxRange())` 和 `world.isLoaded(pos)` 检查
- 配合 `StockKeeperRequestMenuMixin` 解决远距离下单时请求被丢弃的问题
- 问题：两者配合仍无法稳定工作，存在竞态和时序问题
- 修复失败

## 根因总结

1. **网络包竞态**：S2C 注册包和 openScreen 包走不同频道（ModSimpleChannel vs Forge 内部），客户端处理顺序不可控
2. **Level.getBlockEntity 是维度的强制依赖**：`createOnClient` 中硬编码了 `Minecraft.getInstance().level`，无法绕过维度限制
3. **假 BE 状态不完整**：构造的 `StockTickerBlockEntity` 没有 level/behaviours，Screen 的部分操作会发送 C2S 包到错误维度或不可用状态
4. **服务端缓存污染**：在 `LevelMixin.getBlockEntity` 中做全局拦截会影响所有维度的 BE 查询，导致假包

## 可行的方向（如果继续的话）

- 放弃复用 Create 的 GUI，在 SpellResult 中自己发送 S2C 包携带库存数据 + 在客户端用自定义 Screen 渲染（类似 StressArkHUD 模式—纯数据驱动，不依赖 BE）
- 或者接受同维度短距离限制
