## 症状

为应力聚晶和应力护盾聚晶添加 tooltip 缓存的 NBT 值（`cached_damage` / `cached_shield`），走 Ark 路径时 tooltip 始终显示 0，绑定 Reader 路径正常。

## 根因

Goety 的 `WandUtil.findFocus(caster)` 返回的是**法杖内部**的焦点 ItemStack（通过 `IWand.getFocus(wand)` 从法杖 NBT 中取出的副本），而非玩家背包/快捷栏中的焦点物品。

- `SpellResult` 中调用 `updateDamageCache(focus, damage)` 修改的是法杖**内部副本**的 NBT
- `appendHoverText` 中 tooltip 读取的是背包中**独立焦点物品**的 NBT
- 两者是不同 Java 对象，NBT 修改互不影响

绑定 Reader 路径能正常显示，是因为绑定操作（`bindToReader`）是玩家**手持焦点**右键 Reader 方块时执行的，修改的是背包物品的 NBT。走 Ark 路径时焦点可能从未被手持操作过。

## 修复

改用**客户端动态计算**：`StressArkHUD` 已持有 Ark 的 `totalCapacity` 数据（通过 S2C 包同步），tooltip 中直接从客户端缓存计算伤害/护盾值：

```java
float cap = StressArkHUD.getTotalCapacity();
int damage = Math.max(1, (int) (cap / ModConfig.STRESS_DAMAGE_DIVISOR.get()));
```

绑定 Reader 路径仍用 NBT 缓存（该路径下焦点必定被手持绑定过，NBT 存在）。

## 经验提炼

**不要依赖 WandUtil.findFocus() 返回的 ItemStack 做 NBT 持久化**。它返回的是法杖内部副本，修改不会同步到背包物品。对于 tooltip 需要显示的数据，优先走客户端缓存/动态计算。
