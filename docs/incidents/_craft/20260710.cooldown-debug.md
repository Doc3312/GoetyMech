# Goety 冷却排查经验

## 现象

兵团聚晶召唤仆从后进入冷却，但 shift+右键（法杖持有聚晶）后冷却被清除。

## 排查过程

### 第一阶段：假设 NBT 变更导致 cooldownsSpecific key 失效

`FocusCooldown.keyOf(ItemStack)` = `itemID + stack.getTag().toString()`。当 NBT 改变时 key 改变，`cooldownsSpecific` 查询不到原有冷却。

但我们的 `SEHelper.addCooldown(player, focus.getItem(), cd)` 使用 `cooldowns` map（Item 层级，不依赖 NBT），`isOnCooldown(Item)` 应检测到。

**结论：** 假设错误，NBT 变更不是原因。

### 第二阶段：假设 cannotCast() 跳过冷却检测

加入 DEBUG 日志后发现 `SpellResult` 中 `onCooldown=false`。但冷却已自然过期（10s 冷却，14 秒后检查）。

### 第三阶段：尝试 FocusCooldownMixin（拦截 removeCooldown）

拦截 `removeCooldown(Player, Level, Item)` — 发现会同时阻止 shift+dismiss（dismiss 需经过 `cannotCast()` 才能到达 `SpellResult`）。

### 第四阶段：尝试 DarkWandUseMixin @At("HEAD")

在 `DarkWand.use()` 最开头拦截 SquadFocus shift+右键。但 HEAD 注入导致非 shift 的召唤变为"点按"而非"长按"。

### 最终方案：DarkWandUseMixin @At("INVOKE")

注入点改为 `getFocus` 调用之后、`cannotCast()` 之前。shift+SquadFocus 在此直接 dismiss 返回 `sidedSuccess`，跟 CommandFocus/OrderFocus/CallFocus 完全相同的模式。

**冷却清除的根因始终未定位到具体代码路径。** 但通过设计模式匹配（其他 Focus 都是这么处理的），绕过了问题。

## 教训

- Goety 的冷却系统有 `cooldowns`（Item 级）和 `cooldownsSpecific`（NBT 依赖级）两个 map，调试时需区分
- 非自己写的冷却代码，排查不如直接匹配 Goety 既有模式绕过
- CommandFocus/OrderFocus/CallFocus 的 shift 处理都在 `DarkWand.use()` 的 `cannotCast()` **之前**
- `SpellResult` 中的 shift 检查（`isShifting`）实际上只在法杖施法路径中可达，存在冷却封锁新矛盾
- Mixin 注入点的选择至关重要：`@At("HEAD")` 会跳过所有前置逻辑（包括 `getFocus`），而 `@At("INVOKE")` 可以精确插入到目标方法调用后
