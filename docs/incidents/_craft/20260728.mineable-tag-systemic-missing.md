# 系统性缺失 mineable/pickaxe 标签

## 现象

所有方块（12 个注册方块）均未加入 `data/minecraft/tags/blocks/mineable/pickaxe.json` 标签。
其中 6 个方块调用了 `requiresCorrectToolForDrops()` 但无对应 mineable 标签 → 任何工具破坏均不掉落。

## 受影响方块

| 修复类型 | 方块 | requiresCorrectToolForDrops | 修复内容 |
|---------|------|:---:|---------|
| tag + loot | tier1/2/3_squad_barracks | ✅ 是 | mineable/pickaxe + 新建 loot table |
| tag 修复 | stress_reader | ✅ 是 | mineable/pickaxe（已有 loot） |
| tag 修复 | remote_engine | ✅ 是 | mineable/pickaxe（已有 loot） |
| tag 修复 | flesh_furnace | ❌ 否 | mineable/pickaxe（已有 loot） |
| tag 修复 | breeding_nest | ❌ 否 | mineable/pickaxe + 修复空 loot |
| 不动 | stress_ark | ✅ 是 | 故意保留（用户要求不设挖掘） |
| 不动 | soul_monument ×3 | ❌ 否 | strength(-1.0F) 不可破坏 |
| 不动 | crater | ❌ 否 | air 方块 |

## 根因

新建方块时未同步创建 `data/minecraft/tags/blocks/mineable/pickaxe.json`。
Goety 主模组有大面积内部标签体系（#goety:* → mineable/pickaxe），但本项目直接沿用 Goety 注册惯例时遗漏了标签注册环节。

## 教训

1. 新方块必须三件套：block class + loot table + mineable tag（或者显式 `.noLootTable()`）
2. `requiresCorrectToolForDrops()` 必须配合 `mineable/*` 标签，否则破坏不掉落
3. 可以使用 Goety 的内部标签风格（如 `#goetymech:metal_blocks`）统一管理同族方块，降低遗漏概率
