## 症状

魂灵丰碑在放置后录入仆从，HUD 显示正常。破坏后重新放置同一物品，即使 `.dat` 文件存在，HUD 也不再显示仆从姓名。

## 根因

破坏时（`SoulMonumentBlock.use` shift+空手）只将 `savedEntityUUIDs` 写入 `MonumentUUIDs` NBT，漏掉了 `savedEntityNames`。放置时 `setPlacedBy` 只恢复 UUID，`savedEntityNames` 保持空列表，HUD 渲染空白。

## 修复

- openspec: `fix-soul-monument-hud-names`
- 文件：`SoulMonumentBlock.java:63-72`, `SoulMonumentBlock.java:103-119`, `SoulMonumentBlockEntity.java:213-218`

## 经验提炼

**模式：BlockEntity 数据跨破坏/放置循环的持久化**。

当需要在 block break 时将 BE 内部状态保留到 ItemStack，并在 re-place 时恢复时：

1. **必须明确枚举所有需保留的字段**，不能依赖「UUID 足够」的隐含假设
2. **破坏侧和放置侧必须对称**：save 了多少字段，restore 就必须 restore 同样多的字段
3. **建议用版本化的复合条目**：将每项数据（UUID + Name + 可扩展字段）打包成一个 CompoundTag 条目存入 ListTag，而非平行维护多个 ListTag
4. **设计提示**：`SoulMonumentBlock` 的 `MonumentUUIDs` ListTag 条目格式从 `{UUID}` 升级为 `{UUID, Name}` 后，旧数据仍可被 `load()` 中的 `.dat` 回填逻辑兜底
