# LivingAttackEvent vs LivingHurtEvent 取消伤害的视觉差异

## 问题

取消伤害时使用 `LivingHurtEvent.setCanceled(true)` 虽然不掉血，但受击效果（hurtTime 红闪、击退、受伤音效、红屏覆盖层）**已经发生过**，无法撤回。

## 根因

Forge 事件管道顺序：
```
hurt() → LivingAttackEvent → actuallyHurt()(设 hurtTime/击退/音效) → LivingHurtEvent
```

`LivingHurtEvent` 触发时视觉效果已被 `actuallyHurt()` 写入。

## 解决方案

使用 `LivingAttackEvent.setCanceled(true)` 取代。该事件在 `hurt()` 入口处触发，取消后整个方法 `return false`，没有任何后续副作用。

## 适用场景

想完全屏蔽受击表现（如护盾/免伤/无敌帧）时，必须在 `LivingAttackEvent` 取消，不能在 `LivingHurtEvent` 取消。

## 参考

- Goety 壁垒聚晶: `ModEvents.AttackEvent()` 在 `LivingAttackEvent` 取消
- Prototype 原实现: `PrototypeEvents.onLivingHurt()` → 改为 `onLivingAttack()`
