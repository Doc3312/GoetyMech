# 消耗反馈回路：数据源与显示分离问题

status: verified

## 问题

Engine 的本地网络消耗（stress）反馈回 Reader/Ark 时，Reader 的 `addToGoggleTooltip()` 直接调 `StressLinkService.get(level)`，但该方法在**客户端返回 null**。Create 的护目镜工具提示在客户端本地生成，Service 数据仅服务端可用，导致 Reader 的「引擎消耗」行永不显示。

## 根因

`addToGoggleTooltip()` 在 Client 和 Server 两端都可能被调用。`StressLinkService.get(level)` 对 `level.isClientSide` 返回 null。Service 是纯服务端 Singleton，客户端无法直接访问。

## 教训

| 教训 | 说明 |
|------|------|
| **goggle tooltip 是客户端 UI** | 虽然 Create 有一次服务端 packet 交互，但渲染层数据必须同步到客户端才能稳定显示。Service 查询不可靠 |
| **同步字段 > Service 查询** | BE 应使用 NBT 同步字段存储引擎消耗值，`addToGoggleTooltip()` 直接读字段而非 Service |
| **Engine 的 `this.stress` 可用** | 因为 `KineticBlockEntity.stress` 通过 `updateFromNetwork()` 自动同步到客户端，Engine 工具提示直接读它没问题 |
| **Reader 没有类似同步字段** | Reader 的 `remoteEngineConsumption` 需新增字段 + NBT 写入，在 `pushToEngine()` 时顺便写入 |

## 跨网络应力会计问题

用户核心诉求：Engine 消耗的应力在会计上必须有对应。Reader 显示 147456 可用，Engine 吃了 90112，系统应显示 57344，不能凭空产生。当前：

- ✅ Ark HUD：已正确显示净可用（Reader 可用扣 Engine 消耗）
- ❌ Reader：工具提示 + comparator 信号未扣减
- ❌ Engine：工具提示正确但「Source: /」行已删

修复方向：Reader 新增 `remoteEngineConsumption` 字段 + NBT 同步，`pushToEngine()` 时写入，`addToGoggleTooltip()` 和 `getAnalogOutputSignal()` 扣减此值。

## Auto-pool 重评

当前架构（StressLinkService SavedData + 事件驱动 push + 无全局静态）比 auto-pool 死亡螺旋时期稳定。可尝试简化版 Ark 自动分配：

- Engine 放置时查 `Service.getArksForOwner(placerUUID)`
- 有 Ark → 自动取第一个绑定的 Reader
- 无 Ark → 维持手动绑定
- 关键：Reader 仅 1:1 给 Engine（非多 Engine 池），避免 budget 过度分配
