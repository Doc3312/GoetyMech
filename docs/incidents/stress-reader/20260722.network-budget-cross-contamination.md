## 根因

### 根因 1：预算交叉污染

```
readerStress = localMachineStress + injected_A + injected_B
其中 injected = remoteEngineConsumption / speed × |speed| ≈ remoteEngineConsumption

Reader A: localStress = readerStress - cons_A
         = localMachine + cons_A + cons_B - cons_A
         = localMachine + cons_B  ← B 的消耗被当作本地负载！
budget_A = capacity - localStress_A = capacity - localMachine - cons_B
          ← A 认为 B 的消耗占用了可分配预算
```

### 根因 2：缓存 `readerNetworkKey` 时序空洞

初始方案用 `readerNetworkKey` 缓存追踪 reader 所属网络。但因 `initialize()` 时序问题——`KineticBlockEntity` 的 `network` 字段在 `onReaderLoad()` 时可能尚未被 `RotationPropagator` 赋值——导致 `readerNetworkKey` 在某些读取器上为空，去重失效。

### 根因 3：`updateFromNetwork()` 守卫条件跳过

当两次 propagate 之间 cap/stress 无变化时，`prevCap != cap || prevStress != stress` 为 false → `onReaderNetworkChanged()` 不触发 → `readerNetworkKey` 也未更新。

## 修复

### 修复 1：网络级预算分配（`tick()` → `distributeForNetwork()`）

```
tick() 将 dirtyReaders 按 KineticNetwork identity 分组
→ 对每组调用 distributeForNetwork()
→ totalRemoteConsumption = Σ 同网络所有读取器的 getEngineConsumptionForReader()
→ localStress = max(0, totalNetworkStress - totalRemoteConsumption)
→ totalBudget = max(0, capacity - localStress)
→ 分配给同网络所有引擎
```

在 `distributeForNetwork()` 中使用 `suppressEngineUpdates` 重入防护，保留原有 try/finally 模式。

### 修复 2：实时引用去重（`getAggregatedReaderData()`）

摒弃 `readerNetworkKey` 缓存方案，改为直接从 `activeReaders` 读取活跃 BE 的实时 `getOrCreateNetwork()` 引用：

```java
Set<KineticNetwork> seenNetworks = new HashSet<>();
for (GlobalBlockPos readerPos : getReadersForOwner(ownerUUID)) {
    StressReaderBlockEntity liveReader = activeReaders.get(readerPos);
    if (liveReader != null && liveReader.hasNetwork()) {
        KineticNetwork network = liveReader.getOrCreateNetwork();
        if (!seenNetworks.add(network)) continue;
    }
    // ... 读取数据
}
```

`KineticNetwork` 由 Create 的 `RotationPropagator` 保证同一逻辑网络使用同一实例，identity 比较 (`HashSet` + `==`) 可靠。

### 修复 3：`StressArkBlockEntity.refreshStats()` 改用新聚合方法

删除手动遍历求和，委托给 `getAggregatedReaderData()`。

## 经验提炼

| 教训 | 说明 |
|------|------|
| **实时引用 > 缓存事件** | BE 生命周期事件的执行时机（`initialize()` 时网络可能未就绪）可能导致缓存写入空洞。直接从 `activeReaders` 读实时引用无此问题 |
| **Create 网络 identity 可靠** | `KineticNetwork` 在服务端用同一实例，`HashSet` identity 比较可用于去重 |
| **suppressEngineUpdates 模式可复用** | `distributeForNetwork()` 沿用原有 try/finally 模式，正确阻断 Engine→Reader 递归 |
| **多读取器同网络时 budget 公式需网络级共享** | 旧的 `capacity - readerStress + thisEngineConsumption` 只对单读取器有效，多读取器时必须全局聚合 |
| **convergence 保证** | 第二轮 push 时 `setRemoteEngineConsumption()` 的 `Float.compare` 短路 + Create 的 `updateStress()/updateCapacity()` 值不变短路，确保 1-2 tick 内收敛 |
