## 症状

穿着原型胸甲在水中按 W 游泳时，速度呈指数级增长，远超过预期 9 倍（`SWIM_MAX_MULTIPLIER=8.0`），实际 10+ tick 后已飞出地图。

## 根因

`PrototypeTravelMixin.java:151`，`gp$onTravelWater`：

```java
double newHSpeed = hSpeed * (1.0 + amount);
```

`hSpeed` 是当前实时水平速度，已包含上一 tick 的加成。每 tick 乘以 `(1.0 + amount_i)` 且 `amount_i` 随 tick 从 0 递增到 8.0，最终形成叠乘：

```
∏(1.0 + k/10) for k=1..79 ≈ 10^51 倍
```

## 修复

记录首次进入游泳时的基准速度，改为加法累加：

```java
double newHSpeed = hSpeed + baseSpeed * amount;
```

## 经验提炼

Minecraft 每 tick 速度修正中，对速度做"递增"修改时必须区分：

1. **乘法模型**（compound risk）：`v_new = v_current × factor` — 当 `v_current` 已经包含历史加成时会叠乘爆炸
2. **加法模型**（safe）：`v_new = v_current + base × delta` — 以固定基准做增量，不会叠乘

超过 1 tick 的持续加速，必须用加法模型并记录基准速度。不能直接在当前速度上乘增长率。
