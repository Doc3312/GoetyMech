# Mimic 物品渲染：builtin/entity 与 item/generated 的 base pose 冲突

status: verified

## 症状

`Prototype Mimic` 的渲染无法同时满足两个场景：

- 方案 A：`prototype_mimic.json` 使用 `parent: builtin/entity`，`MimicItemRenderer` 直接渲染源模型。
  - GUI 中盔甲图标平铺显示（正确）。
  - 第一人称手持时源模型平躺在手心，没有正常手持角度（错误）。
- 方案 B：在 JSON 中应用源物品的 display transform（`item/generated` 标准值）。
  - 手持角度正确。
  - GUI 中盔甲被 `[30, 225, 0]` 旋转，变成斜的（错误）。
- 方案 C：把 `parent` 改为 `item/generated`。
  - BEWLR 不再触发，`MimicItemRenderer` 完全失效，物品显示为 `layer0` 的 prototype 图标，源盔甲不渲染（错误）。

## 根因

1. **BEWLR 触发条件**：Forge/Minecraft 只在模型 `parent` 为 `builtin/entity`（或 `BakedModel.isCustomRenderer() == true`）时调用 `BlockEntityWithoutLevelRenderer.renderByItem()`。改成 `item/generated` 会直接破坏伪装机制。
2. **base pose 差异**：
   - `builtin/entity` 进入 `renderByItem()` 时，外层 pipeline 对 GUI 应用的是 identity。
   - `item/generated` 物品在 GUI 下会被外层 pipeline 应用 `[30, 225, 0]` / `0.625` 旋转。
   - 把 `item/generated` 的 GUI transform 硬套到 `builtin/entity` 模型上，会把源模型一起旋转，导致 GUI 歪斜。
3. **手持问题**：`builtin/entity` 本身没有标准手持 transform，所以直接渲染源模型会平躺在手心；需要给它补上手柄姿态。

## 解决方案

在 `prototype_mimic.json` 中保留 `parent: builtin/entity`，并按上下文分别定义 display transforms：

- `firstperson_righthand` / `firstperson_lefthand` / `thirdperson_righthand`：使用 `item/generated` 标准值。
- `ground` / `fixed` / `head`：使用 `item/generated` 标准值。
- `gui`：不定义（identity），源模型平铺显示。

`MimicItemRenderer.renderByItem()` 保持最简：只渲染源模型，不额外 apply transform。

这样外层 pipeline 已经按上下文把 pose 设置好，内部无需关心坐标系差异。

## 文件

- `src/main/resources/assets/goetymech/models/item/prototype_mimic.json`
- `src/main/java/com/goetymech/addon/client/MimicItemRenderer.java`

## 教训

- 不要为了让 BEWLR 之外的渲染“看起来正常”而改 `parent`。`builtin/entity` 是 BEWLR 的触发器。
- Minecraft 的 display transform 是按 `ItemDisplayContext` 独立的，可以利用这一点做“两套姿势”。
- 在 `builtin/entity` 模型上补 `item/generated` 的 transform 是安全的，前提是分上下文补，不要把 GUI 的 3D 倾斜也带进来。
