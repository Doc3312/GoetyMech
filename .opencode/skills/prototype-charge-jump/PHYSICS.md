# 跳跃物理公式 — Minecraft 含 drag 精确速度反算

## 问题：为什么 sqrt(2gh) 不准

真空公式 `v = sqrt(2 * g * h)` 假设**只有重力**减速。但 Minecraft 玩家垂直运动每 tick 还多一步：

```
每个 tick 的垂直运动顺序（LivingEntity.travel()）：
1. 按当前速度移动: y += vy
2. 施加重力: vy -= 0.08
3. 施加 drag: vy *= 0.98
```

`0.98` 的 drag 导致实际高度低于真空公式预测，且偏离随速度增大而加剧。

| 真空公式 | 实际高度（含 drag） | 偏差 |
|---------|-------------------|------|
| h=3 → v=0.693 | ~3.0 | ~0% |
| h=50 → v=2.828 | ~36.0 | **-28%** |
| h=80 → v=3.578 | ~58 | **-28%** |

## 正确公式推导

### 单 tick 递推

```
v_{i+1} = (v_i - 0.08) * 0.98
```

展开得通项：`v_n = (v_0 + 4) * 0.98^n - 4`

位移：每 tick 的移动量就是 `v_n`（移动发生在重力与 drag **之前**）。

### 总高度

设 `v_N` 为最后一个正速度（之后变为负/零）：

```
h = sum_{n=0}^{N-1} v_n
  = (v_0 + 4) * (1 - 0.98^N) / 0.02 - 4N
```

令 `v_N = 0` 求 N：

`(v_0 + 4) * 0.98^N = 4`
`0.98^N = 4 / (v_0 + 4)`
`N = ln(4 / (v_0 + 4)) / ln(0.98)`

代入高度公式：

`h = (v_0 + 4) * (1 - 4/(v_0 + 4)) / 0.02 - 4N`
`= (v_0 + 4 - 4) / 0.02 - 4N`
`= v_0 / 0.02 - 4N`
`= 50 * v_0 - 4 * ln(4 / (v_0 + 4)) / ln(0.98)`

**最终公式**：

```
h(v) = 50 * v  -  4 * ln(4 / (v + 4)) / ln(0.98)
```

## 反求速度：二分法

给定目标高度 h，求需要的初始速度 v。因为 `h(v)` 单调递增，用二分法：

```java
private static double velocityForHeight(double targetH) {
    double lo = 0, hi = 10;
    double ln098 = Math.log(0.98);
    for (int i = 0; i < 50; i++) {
        double v = (lo + hi) / 2;
        double h = 50 * v - 4 * Math.log(4 / (v + 4)) / ln098;
        if (h < targetH) lo = v; else hi = v;
    }
    return (lo + hi) / 2;
}
```

50 次迭代精度 ~1e-15，足够。

## 已知偏差与未解问题

当前公式在 `h >= 50` 段实测偏低（80 → ~60），可能原因：

- **Entity.move() 碰撞迭代**：高速时 `move()` 将大位移拆成子步骤，可能损失部分位移
- **地面起飞覆盖**：START phase 中 `zza > 0 && charge == 0` 代码会将速度覆写为 2.0
- **hurtMarked 副作用**：`hurtMarked = true` 触发位置同步，可能影响第一 tick 移动

如需修复 80→60 偏差，建议先加 log 排除后两个 factor，然后考虑在 `applyChargedJump` 中暂时移除 `hurtMarked = true` 测试。
