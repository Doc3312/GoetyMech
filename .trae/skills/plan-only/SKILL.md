# 方案先行规则

## 何时触发

当用户提出以下类型的请求时，**必须触发此规则**：

- "找下解决方案"
- "分析问题"
- "看看有什么问题"
- "审查代码"
- "给方案"
- "有什么方案"
- 任何要求分析、诊断、找方案的请求

## 行为规则

**除非用户明确说了"修复"、"改代码"、"实施"、"执行"、"开始吧"等表示要动手的指令，否则：**

1. **只输出方案分析** — 解释问题根因、给出可行方案、分析各方案优缺点
2. **不动手修改代码** — 不创建/编辑任何文件
3. **不写代码片段当答案** — 可以用伪代码或简短的代码示意来说明方案，但不要写出完整的可编译代码文件
4. **让用户决定** — 给出方案后等待用户选择，用户选了方案并明确说"执行"才动手

## 例外

用户明确说出以下关键词时，可以跳过此规则直接修复：
- "修复" / "fix"
- "改代码" / "改掉"
- "实施" / "开始实施" / "执行"
- "动手" / "开始改"
- "写代码"
- "按X方案执行"
